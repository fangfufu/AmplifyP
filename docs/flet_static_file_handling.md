# Static Flet Deployment File Handling

This document explains the mechanism used to enable file uploads and downloads
when deploying a Flet application as a static website (Pyodide).

## The Problem

When running Flet as a static web app via Pyodide, the Python code runs inside a
Web Worker. This worker runs in a separate thread from the main UI thread and
does not have direct access to the DOM or standard browser file APIs like
`window.showOpenFilePicker` or `document.createElement('a')`.

Standard Python file operations (`open()`) or Flet's `FilePicker` rely on
platform-specific implementations that may not be fully supported or behave
differently in the Pyodide environment, especially for saving files to the
user's local machine.

## The Solution: Hot Patching

To overcome this, we employ a "hot patching" technique. After the Flet
application is built into static assets (HTML, JS, WASM), we modify the
generated JavaScript files to inject custom message handlers. These handlers
bridge the gap between the Python worker and the browser's main thread.

The script `patch_flet_web.py` performs these modifications on the `dist`
directory generated by `flet publish`.

### 1. File Upload (Opening Files)

To support loading files (e.g., restoring application state), we intercept a
specific message sent from Python to JavaScript.

#### Python Side

In `main.py`, when running in Pyodide, we send a custom message
`open_file_picker` to the JavaScript side:

```python
import js
js.postMessage("open_file_picker")
```

We also set up a callback to receive the file content:

```python
from pyodide.ffi import create_proxy

def on_file_content(content: str) -> None:
    # Process file content
    pass

js.self.custom_file_callback = create_proxy(on_file_content)
```

#### JavaScript Side (`python.js`)

We patch `python.js` to listen for this message. When received, it:

1. Creates a hidden `<input type="file">` element.
1. Programmatically clicks it to open the browser's file dialog.
1. Reads the selected file using `FileReader`.
1. Sends the file content back to the worker via `app.worker.postMessage`.

**Injected Code:**

```javascript
if (typeof event.data === 'string' && event.data === 'open_file_picker') {
    let input = document.createElement('input');
    input.type = 'file';
    input.accept = '.yaml,.yml';
    input.onchange = (e) => {
        let file = e.target.files[0];
        if (!file) return;
        let reader = new FileReader();
        reader.onload = (e2) => {
            app.worker.postMessage({type: 'file_content', content: e2.target.result});
        };
        reader.readAsText(file);
    };
    input.click();
    return;
}
```

#### Worker Side (`python-worker.js`)

We also patch `python-worker.js` to handle the incoming file content message. It
checks for the `file_content` type and invokes the Python callback we registered
earlier (`js.self.custom_file_callback`).

**Injected Code:**

```javascript
if (event.data && event.data.type === 'file_content') {
    if (self.custom_file_callback) self.custom_file_callback(event.data.content);
}
```

### 2. File Download (Saving Files)

To support saving files (e.g., downloading application state), we send a message
containing the file data from Python to JavaScript.

#### Python Side

In `main.py`, we serialize the state to a string (YAML) and send it as an
object:

```python
import js
from pyodide.ffi import to_js

js.postMessage(
    to_js(
        {
            "type": "save_file",
            "filename": "state.yaml",
            "content": yaml_str,
        },
        dict_converter=js.Object.fromEntries,
    )
)
```

#### JavaScript Side (`python.js`)

We patch `python.js` to intercept this object message. When received, it:

1. Creates a `Blob` from the content.
1. Creates an object URL for the blob.
1. Creates a temporary `<a>` element with the `download` attribute set to the
   filename.
1. Programmatically clicks the link to trigger the browser's download behavior.
1. Revokes the object URL to free memory.

**Injected Code:**

```javascript
if (typeof event.data === 'object' && event.data.type === 'save_file') {
    let blob = new Blob([event.data.content], { type: 'text/yaml' });
    let url = URL.createObjectURL(blob);
    let a = document.createElement('a');
    a.href = url;
    a.download = event.data.filename;
    a.click();
    URL.revokeObjectURL(url);
    return;
}
```

## Deployment Workflow

The deployment workflow (defined in `.github/workflows/deploy.yml` and
`build_static.sh`) automates this process:

1. **Build:** `flet publish src/main.py` generates the static site in
   `src/dist`.
1. **Patch:** `python patch_flet_web.py src/dist` injects the custom JS
   handlers.
1. **Deploy:** The patched `src/dist` folder is deployed to GitHub Pages.
